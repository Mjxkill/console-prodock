## Implementation summary
- **Validation**: each record must be a dict with a string `event`; type errors, missing required fields, and invalid containers (`None`, `{}`, `[None]`, `[{'event': 1}]`) all raise `ValueError`. `launch_id` must be a nonempty string; `request_id` must be a nonempty string or an integer (never a bool); `tool_start`/`tool_finish` require a string `name`; `test_finish` requires an int `index` ∈ 0..1023, int `returncode` ∈ −255..255 (never bool), and true booleans `timeout`/`output_limited`.
- **Relevance filtering first**: non-relevant events (`sandbox_start`, `launcher_exit`, …) are ignored *before* identity-field checks — this exact ordering was the one real bug found (first attempt validated `launch_id` before filtering and crashed on lifecycle events).
- **Counting**: outcomes keyed by `(launch_id, request_id, index)` and deduplicated; conflicting repeats of the same identity raise `ValueError`; identical repeats are idempotent. `test_runs` = unique outcomes; `test_failures` = nonzero returncode OR `timeout` OR `output_limited`; `test_calls` = distinct `run_tests` request identities seen in starts OR finishes; `complete` requires run_tests starts to pair with finishes, every outcome to belong to a paired call, and every paired call to carry at least one outcome (empty input is complete with zero runs).
