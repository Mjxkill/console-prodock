Facteurs vérifiés dans le paquet : les ressources natives sont positionnées de `0x800000` à `0x900000` puis `0xa00000` ; les assets LUMA se terminent à `0x16ae000`, donc bien dans `[0x1600000,0x1700000)` ; le natif n’écrit que sur les deux pages de fond ; le RLE `count16/value16` est décodé avec borne `n>pixels-at` ; les halos sont déclarés `GPU_ARGB4444` sans mode bilinéaire dans le code. Donc les anciennes pistes « vies non affichées » et « UV bilinéaires » ne sont pas reproduites ici.

Points vérifiés pour les caches, l’exit/rechargement, la pause et les mini_pixels partagés :

- `page_valid[page]` est bien remis à 0 par `l3_simon_presentation_reset()` ; la re-bake remet `ui_page[0]=ui_page[1]=0`, ce qui force un ré-upload complet de la page utile.
- `chrome()` ne recalcule le cache que si la clé (phase, longueur, index, état/progression, showcase) change ; le compteur `ui_revision` est géré par instance.
- `upload_rect()` compare correctement source partagée `mini_pixels` et ombre par page, et publie par mots alignés 4 octets.
- Les rectangles d’upload bornés pour 720 restent dans la largeur 1280 : sidebar `100+210=310`, centre `575+130=705`, droite `970+240=1210`, commandes `20+1240=1260`.

Limite : le paquet ne contient ni la définition complète de `L3SimonLightFrame`, ni `l3_ui_text`, ni le comportement exact du GPU. Je ne peux donc pas établir un contre-exemple exécutable exact sur le rendu natif. Dans l’état fourni, aucun défaut runtime démontré ne justifie un patch : les régions mémoire testées restent bornées et le cache par page/page_light ne présente pas d’incohérence visible.

Garde recommandée, 30 lignes maximum, pour détecter une future régression du cache lors d’un changement de phase :

```c
L3Render r; setup(&r,1);
L3Game g={0}; l3_arcade_init(&g.activities.arcade);
CHECK(l3_arcade_enter(&g.activities.arcade,L3_ARCADE_SIMON,17));
l3_arcade_step(&g.activities.arcade,0,0,0);
L3ArcadeView v; CHECK(l3_arcade_view(&g.activities.arcade,&v));
l3_simon_presentation_observe(&r,0,&v,0,0,0,0,1);
draw(&r,&g,0);
unsigned rev=r.simon_presentation->ui_revision;
CHECK(l3_arcade_step(&g.activities.arcade,L3_ARCADE_RESTART,0,0)&L3_MINI_EVENT_CHANGED);
l3_arcade_step(&g.activities.arcade,0,0,0);
CHECK(l3_arcade_view(&g.activities.arcade,&v));
l3_simon_presentation_observe(&r,0,&v,0,0,0,1,2);
CHECK(r.simon_presentation->assets_valid==0);
draw(&r,&g,1);
CHECK(r.simon_presentation->ui_revision>=rev);
```

Cette garde vise le cas exact où un rechargement change d’époque et doit réinitialiser les ressources, sans dépendre d’hypothèses visuelles. Absence de preuve, pas de patch forcé.
