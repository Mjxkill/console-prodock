Aucun défaut concret n'est identifiable dans le delta fourni pour le parcours Simon inactif. Le code prépare uniquement la page `r->frame & 1`, tandis que `(r->frame ^ 1) & 1` reste la page frontale testée par snapshot. Le tampon `entry_background` est conservé entre les deux premières utilisations puis libéré seulement quand `base_ready[0] && base_ready[1]`.

Quatre cas vérifiés:

1. Premier passage sur page inactive : `base_ready[page]` est faux; `publish(..., page*r->page_bytes, entry_background, bytes)` écrit le fond sur la page en préparation. Le test `draw` conserve un snapshot de la page frontale et vérifie l'égalité octet par octet; ensuite `base_ready[0]=1` et `entry_background` reste non nul.

2. Deuxième passage et libération du tampon : la page opposée reçoit son fond, `base_ready[1]=1`, puis `free(p->entry_background)` et `entry_background=0`. Le test vérifie précisément ce point : après le deuxième `draw`, `!entry_background && base_ready[1]`.

3. Reset / changement de view ou epoch : `l3_simon_presentation_reset` libère le tampon, remet `base_ready[0/1]=0`, invalide `assets_valid`, `ui_valid`, `page_valid`, puis le premier `draw` rebake et recrée `entry_background`. Le test exerce deux resets successifs, puis `l3_simon_presentation_close` deux fois sans crash.

4. Échec / absence de tampon : prepare retourne 0 si `entry_background` est nul sans publier de fond ni modifier la page frontale; dans bake, chaque échec d'expand/libération libère `work` et retourne 0 sans marquer `assets_valid`. Le test couvre également le parcours complet, les zéros attendus dans les zones mémoire non utilisées et le sentinel front à chaque passage.

Par conséquent, aucun patch minimal n'est proposé sur la base fournie. Les captures oracle ne prouvent pas le timing scanout, mais le contrat source/test garantit que les écritures fond/UI se font sur la page inactive.
