Je vais analyser le paquet fourni : critères de rejet pour le COPY réel, décodage du CE n7630_6, hypothèses classées, puis cas frontières, témoins négatifs et assertions.

## Faits vérifiés sur le paquet fourni

**Le COPY carte est valide selon gpu_copy565.v.** Calcul avec TARGET accepté (color_base 0x00800020, color_stride 256, height 16, clip 0..128 x 0..16) :

| Critère (gpu_copy565.v, bloc CHECK) | Valeur COPY | Résultat |
|---|---|---|
| w1[31:30], w1[4:0] | 0x00808000 | 0, 0 : ok |
| w2[31:16] largeur, w2[15:0] hauteur | 16, 1 | dans [1,1024] et [1,512] : ok |
| w3[31:16], w3[4:0], w3[15:0] >= 2*largeur | 0, 0, 32 >= 32 | ok |
| src_end = w1 + stride*hauteur | 0x00808020 | <= 0x40000000 : ok |
| w7 | 0 | ok |
| overlap = w1 < dst_end && dst_base < src_end | 0x808000 < 0x801020 faux | overlap 0, bit 2 ok |

descriptor_bad attendu = 3'b000. Le bench RTL qui passe confirme ce calcul. Le rejet carte vient donc d'un descripteur vu par u_copy différent de celui envoyé, ou d'un chemin de rejet hors u_copy.

**Le CE n7630_6 est bien la condition de capture RTL, à une inconnue près.** Décodage des deux LUT fournies :
- `l_31_18` : init 0x0001, vrai seulement si state_0[3:0] == 0.
- `n7630_6` : init 0x4000, bit 14, soit I3=1, I2=1, I1=1, I0=0. Donc n7630_6 = l_31_18 && u_pixels/state[41] && gpu_debug_state[50] && !state_0[4].

Soit : état IDLE (5 bits à zéro) ET state[41] ET gpu_debug_state[50]. Le RTL exige `!rst && state==IDLE && start` (gpu_copy565.v, branche IDLE). Le mapping est fidèle si et seulement si state[41] est COPY_START et gpu_debug_state[50] est un alias de child_resetn[0]. Ces deux équivalences ne sont pas dans le paquet. Si gpu_debug_state[50] n'est pas child_resetn[0], la netlist diverge du RTL et la simulation mappée le montrera sans force.

**Deux chemins de rejet incrémentent le même compteur.** gpu_v1.v:428 rejette l'opcode 29 sans démarrer u_copy si target_valid vaut 0. gpu_v1.v:437 rejette si copy_bad. Le témoignage "rejection+1" ne les distingue pas. "source/color/depth inchangés" est attendu dans les deux cas et n'apporte aucune preuve sur le chemin mémoire.

**Le scénario "capture perdue puis rejet" n'existe pas en RTL.** La capture et la transition IDLE vers CAPTURE_WAIT sont dans le même `if(start)` du même `else` de rst. En RTL, perdre la capture implique rester en IDLE, donc jamais de bad. Dans la netlist, le CE du packet (n7630_6) et le CE de state_0 sont des réseaux distincts. Seule une faute physique ou une divergence logique peut les séparer. Une simulation mappée à délai nul ne reproduira ce scénario qu'avec un force, sauf divergence logique sur gpu_debug_state[50].

**Exclusion utile.** Si child_resetn[0] était bas pendant COPY_START, u_copy resterait en IDLE et gpu_v1 bloquerait en COPY_WAIT. La carte rapporte done2, donc u_copy a atteint FINISH ou n'a jamais été démarré. Le "reset enfant encore actif" est exclu comme cause du rejet.

## Hypothèses, erreurs dans les prémisses, preuves manquantes

Hypothèses classées, de la plus à la moins probable selon ce paquet :
- **H1, descripteur zéro dans u_copy (INIT0, capture manquée sur la netlist).** Prédit descriptor_bad = 3'b011 (bits 0 et 1 : largeur et hauteur nulles, bit 2 nul car dst_base < 0 est faux). Cohérent avec done et sans accès mémoire. Nécessite une faute de CE sur les 224 FF, donc une preuve de timing, pas la mention LW.
- **H2, target_valid à 0 au DECODE du COPY (gpu_v1.v:428).** Cohérent avec done et rejet. Demande un reset logiciel ou un TARGET refait entre les deux commandes. Testable sur carte sans mémoire.
- **H3, divergence logique via gpu_debug_state[50].** Si ce bit n'est pas child_resetn[0], la capture est bloquée en permanence sur carte. Prédit un rejet systématique et reproductible en simulation mappée.
- **H4, paquet tronqué en amont.** gpu_geometry.v:258 copie `command` en un cycle. Le debug n'a capturé que w0. Si w1..w3 étaient nuls à l'entrée de gpu_v1, le résultat serait identique à H1. TARGET a passé par la même voie avec w3 et w4 non nuls, ce qui affaiblit H4 sans l'exclure.

Erreurs ou imprécisions dans les hypothèses fournies :
- Le bench RTL rapporte reads=2 writes=2 alors que le texte annonce 1 lecture et 1 écriture. Avec lane source 0 et count 16, un COPY unique fait exactement 1 lecture. Soit le test contient deux COPY, soit la commande simulée diffère de celle de la carte. À clarifier avant d'invoquer ce bench comme référence.
- Un témoin RTL de capture perdue doit déposer 256'd0 dans u_copy.packet avant start. Sans cela le packet RTL vaut X, `if(|descriptor_bad)` avec X prend la branche BOUNDS, et le témoin donne un faux "accepté". Le mapping INIT0 vaut zéro, pas X.
- Le rejet COPY ne dit rien du chemin mémoire : u_copy rejette en VALIDATE avant tout READ0. Le blocage des CLEAR est un symptôme indépendant à traiter séparément.

Preuves manquantes à fournir :
- Le pilote de gpu_debug_state[50] dans la netlist routée, et la ligne `assign gpu_debug_state` dans gpu_v1.v.
- La valeur de localparam COPY_START dans gpu_v1.v, pour valider state[41].
- Le pire slack setup des chemins terminant sur `u_copy/packet_*_s0.CE` dans le rapport de timing R19. LW est une ressource de routage pour forts fanouts, pas une faute.
- La séquence carte exacte entre reload et COPY : reset logiciel émis ou non, nombre de COPY déjà envoyés.
- Les mots w1..w3 du packet gpu_v1 au cycle DECODE du COPY, si le capteur debug peut y pointer.

## Cas frontières, témoins négatifs, assertions

Tous les cas utilisent le TARGET carte inchangé. Variation d'un seul mot par rapport au COPY de référence C0. Attendu = descriptor_bad[2:0].

| Cas | Mot modifié | Attendu | Remarque |
|---|---|---|---|
| C0 | aucun | 000 | 1 lecture, 1 écriture, done, bad 0 |
| E0 | w6 = 0 | 000 | accepté mais vide : l >= r en CLIP, aucune transaction |
| Z | packet forcé à 0 | 011 | témoin capture manquée après INIT0 |
| A1 | w1 = 0x00808001 | 001 | w1[4:0] non nul |
| A2 | w1 = 0x40808000 | 101 | w1[31:30] et src_end > 0x40000000 |
| A3 | w2 = 0x00000001 | 001 | largeur 0 |
| A4 | w2 = 0x04010001, w3 = 0x00000820 | 001 | largeur 1025, stride 2080 isole le bit 0 |
| B1 | w2 = 0x00100000 | 010 | hauteur 0 |
| B2 | w2 = 0x00100201 | 010 | hauteur 513 |
| B3 | w3 = 0x00000010 | 010 | stride 16 < 32 |
| B4 | w3 = 0x00000021 | 010 | stride non aligné 32 |
| B5 | w3 = 0x00010020 | 010 | w3[31:16] non nul |
| D1 | w7 = 1 | 100 | seul u_copy teste w7, gpu_v1 ne le fait pas pour l'opcode 29 |
| D2 | w1 = 0x3fffffe0, w2 = 0x00100002 | 100 | src_end 0x40000020 |
| D2' | w1 = 0x3fffffe0, w2 = 0x00100001 | 000 | src_end exactement 0x40000000, accepté |
| D3 | w1 = 0x00800040 | 100 | overlap avec base différente |
| D4 | w1 = 0x00800020, w3 = 0x00000040 | 100 | overlap, base égale, stride 64 != 256 |
| D5 | w1 = 0x00800020, w3 = 0x00000100 | 000 | overlap conforme, reverse 0, auto-copie 1 lecture 1 écriture |

E0 est le discriminateur clé sur carte, sans modification ni accès DDR. Un packet correctement capturé donne accepté. Un packet nul donne 011 et rejet. Séquence carte proposée, dans cet ordre, après reload :

1. TARGET carte. Attendu : accepté.
2. SCISSOR (opcode 23) rect 0,0 à 128,16, w3..w7 nuls. Attendu : accepté. Un rejet ici prouve target_valid à 0 (H2) sans toucher la mémoire.
3. E0. Attendu : accepté, pas de DDR. Un rejet ici avec l'étape 2 acceptée isole u_copy (H1, H3 ou H4).
4. E0 une seconde fois. Rejet persistant oriente vers H3 ou H4. Rejet unique puis acceptation oriente vers H1.
5. D1. Attendu : rejet. Contrôle positif du compteur.

Témoin négatif 1, capture manquée après configuration. Mappé : forcer `n7630_6` à 0 pendant le cycle COPY_START de C0, puis relâcher. RTL : déposer 256'd0 dans u_copy.packet au reset, forcer packet à 0 durant le cycle où start est vu, relâcher au cycle suivant. Attendu dans les deux cas : descriptor_bad 011 au cycle VALIDATE, bad 1, done cinq cycles après start, copy_valid jamais à 1, rejected de gpu_v1 incrémenté une fois.

Témoin négatif 2, reset logiciel qui ne vide pas packet. Exécuter C0 complet. Pulser child_resetn[0] bas un cycle avec u_copy en IDLE. Vérifier que packet vaut encore C0 et que descriptor_bad vaut 0. Envoyer C1 = C0 avec w1 = 0x00808040. Attendu capture correcte : READ0 émet addr dérivé de 0x00808040. Forcer ensuite la capture manquée sur C1 : le packet garde C0, bad reste 0, READ0 émet l'adresse de C0. C'est une copie silencieusement mal dirigée, pas un rejet. Les deux témoins ont donc des signatures opposées, ce qui justifie l'assertion de fraîcheur ci-dessous.

Assertions SVA à lier par `bind` sur gpu_copy565 et gpu_v1, sans toucher aux sources gelées :

```systemverilog
// bind gpu_copy565 copy_checks u_chk(.*);
module copy_checks(input clk, rst, start, input [255:0] command, packet,
    input [4:0] state, input [2:0] descriptor_bad, input bad, valid, done);
  localparam IDLE=0, CHECK=1, VALIDATE=17;
  default clocking cb @(posedge clk); endclocking
  // Capture : un cycle après start en IDLE, packet est la commande présentée.
  a_capture: assert property (disable iff(rst)
      (state==IDLE && start) |=> packet==$past(command));
  // Fraîcheur : en CHECK, le descripteur est celui de gpu_v1 (command y est stable).
  a_fresh: assert property (disable iff(rst) (state==CHECK) |-> packet==command);
  // Rejet avant toute transaction.
  a_bad_no_bus: assert property (disable iff(rst) !(bad && valid));
  a_bad_latency: assert property (disable iff(rst)
      (state==IDLE && start) |-> ##4 (state==VALIDATE) ##1 (bad == |$past(descriptor_bad)));
  // Témoin Z : signature exacte d'un packet nul.
  a_zero_sig: assert property (disable iff(rst)
      (state==VALIDATE && $past(packet[255:32])==0) |-> descriptor_bad==3'b011);
  // Valeur attendue du cas, fournie par le bench.
  a_expected: assert property (disable iff(rst)
      (state==VALIDATE) |-> descriptor_bad==tb_pkg::expected_bad);
endmodule
```

```systemverilog
// Côté gpu_v1 : distinguer le chemin de rejet.
a_copy_started: assert property (@(posedge clk) disable iff(!child_resetn[0])
    (state[DECODE] && w0[31:24]==29 && target_valid) |=> state[COPY_START]);
c_bad_428: cover property (@(posedge clk) state[DECODE] && w0[31:24]==29 && !target_valid);
c_bad_437: cover property (@(posedge clk) state[COPY_WAIT] && copy_done && copy_bad);
// Simulation mappée uniquement : le CE est la condition RTL.
a_ce_mapped: assert property (@(posedge gpu_clk)
    u_copy.n7630_6 == (child_resetn[0] && u_pixels.state[COPY_START] && u_copy.state_0==5'd0));
```

Si le run mappé fait échouer `a_ce_mapped` ou `a_capture` sans force, la divergence est logique (H3) et le bit gpu_debug_state[50] est le premier suspect. Si le run mappé passe tous les cas y compris E0, la cause est physique ou de séquence carte, et seule la combinaison slack sur `packet_*_s0.CE` plus séquence SCISSOR, E0, E0, D1 sur carte permet de trancher sans modifier le design.
