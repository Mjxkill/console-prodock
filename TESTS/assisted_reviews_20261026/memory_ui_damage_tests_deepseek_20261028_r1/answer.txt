**Revue contradictoire — aucun test exécuté.** Le paquet ne fournit ni noms de fichiers ni numéros de lignes ; je cite donc les symboles et expressions exacts.

## Faits

- `ui()` fait `memset(f->ui,0,w*h)`, redessine tous les textes, puis `publish(...,f->ui,w*h)` uniquement si `ui_revision[page]!=f->revision`, avec `page=r->frame&1`.
- `f->ui` est déclaré `uint8_t *` dans `L3MemoryScene`. Le plan « 2 shadows, max 1,8432 MB au total à 1280×720 » correspond exactement à `2×1280×720` octets : l’hypothèse implicite est donc une UI 8 bits indexée, comparée par mots de 32 bits (4 pixels). Ce n’est pas une UI 32 bits/pixel.
- `l3_memory_scene_render()` valide `r->width`, `r->height`, `r->pitch`, `r->page_bytes`, puis appelle `art()`, `board()`, `ui()`.
- Le header contient `page_valid[2]`, `base_ready[2]`, `ui_revision[2]`, mais aucun champ de validité des shadows UI. `l3_memory_scene_invalidate()` est seulement déclaré/commenté ; son corps n’est pas fourni.
- Le pointeur de couche `l[0]` est réécrit à chaque appel de `ui()`, après le bloc `if` : le changement de page ne laisse pas nécessairement un pointeur UI périmé, mais les shadows doivent rester par page.

## Hypothèses bloquantes / preuves manquantes

1. **Format UI** : si `l3_ui_text()` écrit des pixels 32 bits, alors `memset(...,w*h)` et `publish(...,w*h)` sont sous-dimensionnés, et 1,8432 MB pour deux shadows est faux (il faudrait 7,3728 MB à 1280×720). Preuve à fournir : code de `l3_ui_text()` et sémantique exacte de la longueur de `publish()`.
2. **Invalidation** : le commentaire du header promet une republication, mais rien ne prouve que `ui_revision` ou une validité UI soit détruite. Un simple `ui_revision[page]=UINT_MAX` ne suffit pas si le dirty scan compare encore à une shadow périmée.
3. **Allocation/redimensionnement** de `f->ui` et des shadows : absent du paquet.
4. **Transparence** : index 0 = transparent ou couleur réelle ? Le dirty scan doit comparer les octets/zéros, pas ignorer les pixels « alpha 0 ».

## 4 contre-exemples concrets

### 1. Première publication / invalidation : zéros non écrits

VRAM page 0 = `0xA5`, shadow page 0 = zéros, `valid=0`. Si le code ne force pas un full mais compare source et shadow, les zones UI restées à zéro ne sont pas publiées : `0xA5` reste. Même problème après `l3_memory_scene_invalidate()` : un autre mode écrase les 20 MiB, la révision ne change pas, la shadow est identique à `f->ui`, donc span vide.

Patch minimal :
```c
unsigned ui_valid[2], ui_full[2];

void l3_memory_scene_invalidate(L3MemoryScene *f) {
    f->ui_valid[0] = f->ui_valid[1] = 0;
    f->ui_full[0]  = f->ui_full[1]  = 1;
}

/* dans ui() */
if (f->ui_revision[p] != f->revision || !f->ui_valid[p]) {
    memset(f->ui, 0, n);
    /* redessin identique */
    if (f->ui_full[p]) {
        publier_tout(f->ui, n);          /* y compris les zéros */
        memcpy(f->shadow[p], f->ui, n);
        f->ui_full[p] = 0;
    } else {
        publier_span_dirty(f->ui, f->shadow[p], n);
    }
    f->ui_valid[p] = 1;
    f->ui_revision[p] = f->revision;
}
```
Sans `ui_full`, le premier full et l’invalidation sont faux.

### 2. Texte raccourci / pixels transparents

La ligne `snprintf(s,...,"Prochain ciel : %u cartes",...)` peut passer de `"Prochain ciel : 30 cartes"` à `"Prochain ciel : 9 cartes"`. Le `memset` actuel efface l’ancienne queue ; un dirty scan qui ne parcourt que la nouvelle bounding-box, ou qui saute les octets source nuls, laisse les anciens glyphes.

Patch : comparaison 32 bits exacte, zéros inclus :
```c
uint32_t a,b;
memcpy(&a, src+i, 4);
memcpy(&b, sh +i, 4);
if (a != b) {
    if (first == n) first = i;
    last = i + 4;
}
```
Ne jamais faire `if (a == 0) continue;`. Le span doit inclure le dernier mot devenu zéro.

### 3. Ligne modifiée hors de la première ligne

La ligne du bas est dessinée à `h-(w==800?30:36)` : si seule `bottom` change, le premier mot différent est loin du début. Un scan qui s’arrête au premier bloc, à la première ligne, ou qui publie seulement la bounding-box du premier texte rate cette ligne.

Patch : deux passes globales, demi-ouvert :
```c
size_t first=n, last=0;
for (size_t i=0; i+3<n; i+=4) { /* comparer */ 
    if (diff) { if (first==n) first=i; last=i+4; }
}
if (first != n) {
    memcpy(dst+first, src+first, last-first);
    memcpy(shadow+first, src+first, last-first);
}
```
Un seul intervalle `[first,last)` est correct mais peut recopier presque tout ; si vous découpez en spans, chaque span doit être émis et arrondi, sans oublier la ligne du bas.

### 4. Resize 800×480 → 1280×720

`w,h` sont dérivés de `r->width*2`/`r->height*2`. Passer de `n=800*480=384000` à `n=1280*720=921600` avec des shadows allouées pour l’ancienne taille provoque lecture/écriture hors allocation. De plus, si `ui_revision[p]==f->revision`, `ui()` ne redessine pas et ne force pas le full.

Patch : mémoriser les dimensions et invalider avant tout scan :
```c
if (f->ui_w != w || f->ui_h != h) {
    uint8_t *a = malloc(n), *b = malloc(n);
    if (!a || !b) { free(a); free(b); return 0; }
    free(f->shadow[0]); free(f->shadow[1]);
    f->shadow[0]=a; f->shadow[1]=b;
    f->ui_w=w; f->ui_h=h;
    f->ui_valid[0]=f->ui_valid[1]=0;
    f->ui_full[0] =f->ui_full[1] =1;
}
```
Il faut aussi vérifier/redimensionner `f->ui` lui-même : le paquet ne montre pas son allocation.

## Banc C court : full copy vs dirty span, 2 pages

Hypothèse du banc : UI 8 bits, `n` multiple de 4. Il compare `full` (référence) et `vram` (publication dirty), sans lecture DDR, avec deux pages, invalidation, texte raccourci, ligne du bas et deux tailles.

```c
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

#define MAXN (1280u*720u)
static uint8_t full[2][MAXN], vram[2][MAXN], shadow[2][MAXN];
static unsigned valid[2], full_req[2];

static void put(uint8_t *s,unsigned w,unsigned x,unsigned y,const char *t){
    for(; *t; t++,x+=8) if(x+8<=w) s[y*w+x]=0x4e; /* alpha 0: pas d'ecriture */
}
static void draw(uint8_t *s,unsigned w,unsigned h,const char *tail){
    memset(s,0,(size_t)w*h);
    put(s,w,10,9,"MEMORY - Les constellations");
    put(s,w,10,h-30,tail);
}
static void full_pub(int p,const uint8_t *s,size_t n){
    memcpy(full[p],s,n);
}
static void dirty_pub(int p,const uint8_t *s,size_t n){
    if(!valid[p] || full_req[p]){
        memcpy(vram[p],s,n); memcpy(shadow[p],s,n);
        valid[p]=1; full_req[p]=0; return;
    }
    size_t first=n,last=0;
    for(size_t i=0;i<n;i+=4){
        uint32_t a,b; memcpy(&a,s+i,4); memcpy(&b,shadow[p]+i,4);
        if(a!=b){ if(first==n) first=i; last=i+4; }
    }
    if(first!=n){
        memcpy(vram[p]+first,s+first,last-first);
        memcpy(shadow[p]+first,s+first,last-first);
    }
}
static void check(int p,size_t n,const char *step){
    if(memcmp(full[p],vram[p],n)){
        fprintf(stderr,"FAIL %s page%d\n",step,p); exit(1);
    }
}
static void run(unsigned w,unsigned h){
    size_t n=(size_t)w*h;
    uint8_t *src=malloc(n); if(!src) exit(2);
    for(int p=0;p<2;p++){
        memset(full[p],0xA5,n); memset(vram[p],0xA5,n);
        memset(shadow[p],0,n); valid[p]=0; full_req[p]=1;
    }
    draw(src,w,h,"Fleches / WASD : choisir   E : retourner   Tab : retour");
    full_pub(0,src,n); dirty_pub(0,src,n); check(0,n,"premier full p0");

    draw(src,w,h,"Ciel complete ! Entree : prochaine constellation");
    full_pub(1,src,n); dirty_pub(1,src,n); check(1,n,"premier full p1");
    check(0,n,"retour p0 sans publication");

    draw(src,w,h,"30 cartes");
    full_pub(0,src,n); dirty_pub(0,src,n); check(0,n,"bas hors premiere ligne");

    draw(src,w,h,"9 cartes"); /* chaine plus courte : zeros a publier */
    full_pub(0,src,n); dirty_pub(0,src,n); check(0,n,"texte raccourci/transparent");

    memset(vram[0],0xA5,n);       /* autre mode ecrase la VRAM */
    valid[0]=0; full_req[0]=1;    /* ce que doit faire invalidate() */
    draw(src,w,h,"A VOUS  /  30 cartes");
    full_pub(0,src,n); dirty_pub(0,src,n); check(0,n,"invalidation");

    free(src);
}
int main(void){ run(800,480); run(1280,720); puts("OK"); return 0; }
```

En supprimant `valid/full_req`, le banc doit imprimer `FAIL premier full p0` ou `FAIL invalidation` : c’est le contre-test minimal. Le chronomètre, s’il est ajouté, doit entourer le scan complet + copie de `dirty_pub`, pas chaque fragment. Les compteurs à retourner sont `scanned += n`, `published += last-first`, `spans++`.

**Verdict** : le plan n’est correct que si (a) l’UI est réellement 8 bits indexée, (b) chaque page a sa shadow et sa validité, (c) `invalidate()` force un full y compris les zéros, (d) le scan compare tous les mots 32 bits, (e) le resize invalide et réalloue. Sans ces cinq points, les quatre cas ci-dessus suffisent à produire des pixels périmés ou des débordements.
