Analyse statique uniquement : je n’ai exécuté aucun test ni touché au FPGA. Les numéros de ligne sont reconstruits depuis le texte fourni.

## Faits saillants

- Le moteur pur est transactionnel sur l’état : `l3_memory_action()` travaille sur une copie locale `n` puis ne commit `*s=n` qu’après validation (`l3_memory.c:46-68`). Un rejet laisse bien `L3Memory` inchangé.
- Le décodeur commit aussi en fin de fonction (`l3_memory.c:106-111`).
- Le conseiller ne lit pas `cards[]` : ses choix utilisent uniquement `known[]` (`l3_memory.c:83-88`). Je n’ai pas trouvé de fuite directe du conseiller par `cards[]`.
- En revanche, plusieurs contre-exemples concernent l’entrée, le curseur, le rendu et la frontière de confiance du codec.

## Contre-exemples concrets

### 1. Input : `Tab`/`q` ne sort pas en mode automatique

**Référence** : `memory_scene.c:72` traite d’abord `if(f->automatic)` et retourne ; la sortie `Tab/q/Q` n’est testée qu’après, `memory_scene.c:74`. L’UI affiche pourtant « Tab : retour » (`memory_scene.c:128`).

**Repro** :
1. `l3_memory_scene_init(&s, seed, 1)`.
2. `l3_memory_scene_key(&s, '\t')`.
3. `s.automatic == 0`, mais `s.exit_requested == 0`.

**Impact** : la première pression sur `Tab` ou `q` ne fait que désactiver l’autoplay ; il faut une seconde pression pour sortir.

**Patch minimal** : traiter les touches de sortie avant la branche automatique.
```c
if(!f) return;
if(c==9 || c=='q' || c=='Q'){ f->exit_requested=1; return; }
if(f->automatic){ ... }
```

**Test discriminant** : dans `scene_probe.c`, initialiser `automatic=1`, envoyer `Tab`, vérifier `exit_requested==1`.

### 2. Input : la première flèche après un takeover `ESC` est avalée

**Référence** : `memory_scene.c:72-73` et le test `scene_probe.c:24`.

Séquence réelle :
1. autoplay actif ;
2. `ESC` → `automatic=0`, `escape=3` ;
3. `[` → `escape=old+1 = 4` ;
4. `A`/`B`/`C`/`D` → `if(old==4)return;` consomme la touche.

Donc `ESC [ C` après takeover ne déplace pas le curseur. Le test `scene_probe.c:24` fige même ce comportement en assertant `cursor==0`.

**Impact** : contradiction avec « Flèches / WASD : choisir » (`memory_scene.c:128`). La première flèche après takeover est perdue.

**Patch minimal** : pour l’état `3` (takeover), passer à l’état flèche `2`, pas à `4`.
```c
if((old==1||old==3)&&c=='['){ f->escape = (old==3)?2:old+1; return; }
```

**Test discriminant** : autoplay, `ESC`, `[`, `C` → attendre `cursor==1` en niveau 0. Mettre à jour `scene_probe.c:24` en conséquence.

### 3. Pose/input : après une paire collectée, le curseur reste sur une carte appariée, le halo disparaît et `E` ne fait rien

**Références** :
- `memory_scene.c:56` : sur `REVEAL`, `cursor = carte retournée`.
- `memory_scene.c:57` : sur `PAIR`, le curseur n’est pas déplacé.
- `memory_scene.c:31` : le halo n’est ajouté que si `!(matched & (1u<<cursor))`.
- `l3_memory.c:49` : un `FLIP` sur une carte `matched` est rejeté.

**Repro** : retourner la première carte, puis sa jumelle, puis `RESOLVE` gagnant. Après la collecte :
- `cursor` pointe la jumelle ;
- cette carte est dans `matched` ;
- `l3_memory_scene_poses()` n’émet plus de pose `id=100` ;
- `E` appelle `FLIP` sur cette même carte, rejeté par les règles.

Le test `scene_probe.c:41` fait exactement la collecte mais ne vérifie pas le curseur après.

**Impact** : curseur invisible et touche d’action apparemment morte jusqu’au déplacement suivant.

**Patch minimal** : sur `PAIR`, repositionner le curseur sur la première carte non appariée.
```c
case L3_MEMORY_PAIR:
 f->pairs++; f->duration=.48f;
 for(unsigned i=0;i<f->view.count;i++)
  if(!(f->view.matched&(1u<<i))){ f->cursor=i; break; }
 break;
```

**Test discriminant** : après `resolve("collect")`, vérifier `!(f.view.matched & (1u<<f.cursor))`, puis après settle, `E` doit produire une action acceptée.

### 4. Rendu/pose : changement de résolution sur la même scène → dépassement de tampon

**Références** :
- `memory_scene.c:85` : `if(f->assets)return 1;` fige les assets à la première résolution.
- `memory_scene.c:86` : `ui` est alloué en `w*h`, `background` en `w*h*2`, avec la résolution du premier appel.
- `memory_scene.c:123` : `memset(f->ui,0,w*h)` utilise la résolution courante.
- `l3_memory_scene_render()` accepte pourtant les deux résolutions `400x240` et `640x360`.

**Repro** :
1. même `L3MemoryScene f` ;
2. premier `l3_memory_scene_render()` avec `r.width=400, r.height=240` → `ui` alloué 800×480 ;
3. second appel avec `r.width=640, r.height=360` ;
4. `art()` retourne immédiatement, puis `ui()` fait `memset(f->ui,0,1280*720)` dans un buffer 800×480.

**Impact** : corruption mémoire côté hôte ; `background` est aussi trop petit pour `board()`.

**Patch minimal** : mémoriser les dimensions d’assets et invalider/réallouer si elles changent.
```c
/* ajouter asset_w, asset_h dans L3MemoryScene */
unsigned w=r->width*2,h=r->height*2;
if(f->assets && f->asset_w==w && f->asset_h==h) return 1;
if(f->assets){
 free(f->ui); f->ui=NULL;
 free(f->background); f->background=NULL;
 f->assets=0;
 f->base_ready[0]=f->base_ready[1]=0;
 f->page_valid[0]=f->page_valid[1]=0;
 f->ui_revision[0]=f->ui_revision[1]=0;
}
...
f->asset_w=w; f->asset_h=h; f->assets=1;
```

**Test discriminant** : rendre une même scène en 400×240 puis 640×360, sous ASan, et vérifier que les deux rendus réussissent.

### 5. Codec/conseiller : `known[]` peut être intégralement forgé sans révélation préalable

**Références** :
- Le contrat indique « `known[]` is previously revealed memory » (`l3_memory.h:24`).
- La validation accepte toute valeur `known[i] == cards[i]` (`l3_memory.c:19`), sans historique de révélation.
- Le décodeur copie `known` tel quel (`l3_memory.c:109`).
- `l3_memory_view()` expose `known` (`l3_memory.c:73`).
- Le conseiller utilise `known` (`l3_memory.c:83-88`).

**Repro concret** :
1. `l3_memory_init(&s,1)` puis `l3_memory_encode(&s,b,128)` ;
2. pour `i < l3_memory_count(s.difficulty)`, faire `b[90+i] = b[60+i]` ;
3. recalculer le CRC sur `b+16,112` ;
4. `l3_memory_decode(&s,b,128)` retourne **1** actuellement.

**Impact** : si la sauvegarde est une frontière de confiance, on peut fournir au conseiller une mémoire parfaite sans aucune révélation, et afficher toutes les faces via `view.known`. Ce n’est pas une lecture de `cards[]` par le conseiller : c’est une triche par sauvegarde. Le CRC32 non authentifié ne l’empêche pas.

**Correctif possible** : soit documenter explicitement que les sauvegardes sont locales et fiables, soit ajouter un historique de révélation/MAC. Un simple CRC ne suffit pas contre l’édition volontaire.

**Test discriminant** : ajouter dans `test_rules.c` le cas `known=cards` avec CRC recalculé. Si l’invariant « previously revealed » doit être garanti, le décodage doit échouer ; si non, le documenter.

## Hypothèses et preuves manquantes

- **`PRODOCK_GPU_BASE`** : `art()` publie aux offsets bruts `FACES`, `CLASSIC`, `6<<20`, `20<<20` (`memory_scene.c:84-92`), alors que `quad()`, `board()` et `ui()` ajoutent `PRODOCK_GPU_BASE` (`memory_scene.c:96`, `:105`, `:132`). Si `PRODOCK_GPU_BASE != 0`, les uploads CPU et les adresses GPU sont décalés. La définition manque : à confirmer avant de conclure.
- **Limite command buffer 492** : `scene_probe.c` assert `commands-start<=492`, mais `gpu_v1_texture/material/quad/target/scissor/copy` et `l3_ui_text` ne sont pas fournis. Impossible de vérifier la borne réelle.
- **Largeur de texte UI** : en 1280, le titre part de `x=250` avec largeur `w-230=1050`, soit fin à 1300 > 1280 (`memory_scene.c:123`). Dépend du clipping de `l3_ui_text`, non fourni.
- **`struct prodock_scene`, `L3_MAP_BYTES`, `L3Render`** : non fournis ; les accès `scene->layers[0]`, `r->memory`, `r->page_bytes` ne peuvent pas être audités complètement.
- **Moteur pur** : aucun contre-exemple trouvé sur les invariants testés de `validate/action/advice`. Les tests `test_rules.c` couvrent bien les rejets transactionnels et la permutation des cartes non vues, mais pas la forge `known=cards`.

## Priorités de correction

1. **Résolution changeante** (`memory_scene.c:85/123`) : risque mémoire réel.
2. **Curseur après paire** (`memory_scene.c:31/56-57`) : défaut utilisateur reproductible.
3. **Takeover/touches** (`memory_scene.c:72-74`) : `Tab` et première flèche incohérents avec l’UI.
4. **Confiance codec** (`l3_memory.c:19/109`) : à trancher explicitement ; sinon le conseiller peut être nourri d’une mémoire forgée.
