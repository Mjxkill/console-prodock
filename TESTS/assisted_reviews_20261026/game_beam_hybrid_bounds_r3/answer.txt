# Bornage rendu hybride — deux profils pages

| Profil | page_bytes | pages / profondeur (base 0x00800000) | pitch | full_image_end (pagebase+) | max_roi_end (pagebase+, cible alignée) |
|---|---:|---|---:|---:|---:|
| 800×480 | 1 048 576 | p0=+0, p1=+1 MiB, Z=+2 MiB | 1600 | 768 000 (`0xBB800`); page end 1 048 576 | ≤ 768 000 ; ex. 512 px à x=288, y=479 |
| 1280×720 | 2 097 152 | p0=+0, p1=+2 MiB, Z=+4 MiB | 2560 | 1 843 200 (`0x1C2000`); page end 2 097 152 | ≤ 1 843 200 ; ex. 512 px à x=768, y=719 |

*Règle page* : `end_roi = pagebase + (y0 + h - 1)*pitch + 2*(x0 + w)` ; exigence `end_roi <= pagebase + page_bytes`, sans débord de u32/u64 et sans recouvrement avec page voisine / profondeur.

# Pseudocode minimal de bornage

```text
legaltarget(Page P, x0,y0, w,h, rangeZ):
  if x0 mod 16 != 0: return false
  if w < 1 or w > 512 or h < 1 or h > 512: return false
  if x0 + w > P.W or y0 + h > P.H: return false
  targetBase = P.base + y0*P.pitch + 2*x0
  endRoi = targetBase + (h-1)*P.pitch + 2*w   # même formule packet
  if endRoi > P.base + P.bytes: return false
  if endRoi > rangeZ.begin or targetBase < rangeZ.end: return false  # pas d'overlap page/Z
  return true
```

Restauration par page, pas par image globale :

```text
for each Page P used this frame:
  Dirty[P] = OldFootprint[P] ∪ NewFootprint[P]
  restoreBgRGB565(P, Dirty[P])        # fond seult, union par page
  for shadow quad if intersects Dirty[P]: draw(4 cmds)
  for body quad if intersects Dirty[P]: draw(4 cmds)
  submit batch <= 64 quads (sync)
```

Le fond statique (blocs) reste pré-rasterisé ; aucune couche dynamique ne le redessine ; le corps utilise la clé zéro, pas alpha.

# Budgets commandes / lots

Hypothèse explicit : **1 quad dynamique = 4 commandes** (material, texture, 2 triangles), puis `TARGET 1 + COPY 1` par lot de 64, `SUBMIT` synchrone. Le plafond 128 quads est une borne à réduire par cull, pas un objectif.

| Scénario | quads | lots 64 | commandes GPU | SUBMIT |
|---|---:|---:|---:|---:|
| 16 corps + 16 ombres + 1 spawn (sans ombre spawn) | 33 | 1 | 33×4 + 2 = 134 | 1 |
| idem si spawn ombré | 34 | 1 | 34×4 + 2 = 138 | 1 |
| 128 pistes | 128 | 2 | 128×4 + 4 = 516 | 2 |
| idem si chaque piste a une ombre compagnon | 256 | 4 | 256×4 + 8 = 1032 | 4 |

Surcoût bande : restauration 488×488 = 476 288 octets destination ⇒ lecture + écriture = **952 576 octets/trame**. La capacité commandes/lots n’est pas une mesure de performance.

# Quatre tests discriminants

1. **Débord page (négatif)** : ROI 512×1 à x=289, y=479 sur 800×480 donne `endRoi = 768 001` (ou image dépassée) ⇒ refus, aucune écriture.
2. **Alignement x (négatif)** : x0=304 est multiple de 16 mais x0=296 avec w=504 touche la même arête droite ; tester x0=290, w=510 ⇒ rejet car `x0 mod 16 != 0`.
3. **Recouvrement page/Z (négatif)** : base+endRoi dans page1 ou dans la zone Z ⇒ rejet ; vérifier que `pagebase + page_bytes` et la base profondeur ne sont pas traversés.
4. **Cache page périmé (négatif)** : mouvement d’un sprite de page0 vers page1 ; la restauration doit cibler l’union old+new **sur chaque page**. Échec attendu si le renderer réutilise un composite d’une autre page ou restaure seulement la dernière image globale.

# Critères proposés (mesurables, pas A/B NEBULA)

Activités instrumentées : `S0` repos, `S1` 16 déplacements+spawn, `S2` 128 changements de piste, `S3` restauration max 488×488. Par activité : **p95/p99/max du temps par trame**, `FPS = 1 000 000 / temps_trame` dérivé sans promesse, nombre de quads, commandes, lots, SUBMIT, octets lus/écrits, surface sale par page. Comparer chaque activité à sa baseline propre et conserver l’exactitude R6 statique (checksum du fond) plus le contour d’alpha réel. Capacité n’équivaut pas à performance.

Hypothèses : une piste comptée comme un quad dynamique ; cible clamped à l’image native ; bases chaînées `page_bytes`. Manquant : contrat exact d’invalidation du cache par page, ordonnancement précis du commandeur, et conditions de cull (scissor).
